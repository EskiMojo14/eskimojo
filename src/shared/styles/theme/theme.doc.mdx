# Theme tokens

`src/shared/styles/theme/` turns each Material 3 theme export into global `--md-sys-color-*` tokens. `theme/index.css` selects the active palette, and `src/shared/styles/index.css` imports it.

```css
.card {
  background-color: var(--md-sys-color-surface-container-low);
  color: var(--md-sys-color-on-surface);
}
```

You always use the same token names. The values change automatically with the user's light/dark setting and the contrast level.

The `on-` prefix means a color for text and icons placed on top of that color. For example, `on-primary` is for text sitting on a `primary` background. Always pair a color with its `on-` partner.

As a quick rule: build pages on `surface` and the container tones with `on-surface` text, and use `primary` for the main action.

## How the theme is chosen

Three independent attributes control the colors: `data-palette` picks goat or arctic, `data-theme` picks light or dark, and `data-contrast` picks the contrast level. Without them, the palette defaults to goat, while theme and contrast follow the operating system. On `<html>`, setting `data-theme="system"` or `data-contrast="system"` has the same effect as omitting that attribute.

| File                      | Contents                                                                                                                                                                                      |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `exports/<name>/*.css`    | The raw Material Theme Builder exports: six files per theme, one per scheme and contrast level. Only read by `scripts/generate-theme.ts`.                                                     |
| `palettes/<name>.gen.css` | Generated by `vp run theme:generate` for each theme directory. Namespaced placeholders such as `%goat-standard` and `%arctic-high`, with light and dark values combined using `light-dark()`. |
| `index.css`               | Selectors that `@extend` those placeholders, plus the `color-scheme` rules for `data-theme`.                                                                                                  |

`%placeholder` and `@extend` come from [postcss-extend-rule](https://github.com/csstools/postcss-extend-rule), configured in `vite.config.ts`. Each placeholder is written once, and its declarations are copied into every rule that extends it. If an `@extend` doesn't match a placeholder, the build fails.

### Palette

Set `data-palette` on `<html>` to `goat` or `arctic`. Removing it restores goat:

```ts
document.documentElement.dataset.palette = "arctic";
delete document.documentElement.dataset.palette;
```

The palette applies to the whole document and combines with all light/dark and contrast settings, including contrast overrides on individual elements.

### Light and dark

Each token uses `light-dark()`, which picks a value from the `color-scheme` of the element where the token is used. `index.css` sets `color-scheme: light dark` on `:root`, so the theme follows `prefers-color-scheme` by default. Browser UI such as form controls and scrollbars switches with it.

To choose a theme explicitly, set `data-theme` to `light` or `dark`. On `<html>`, remove it or set it to `system` to follow the system again:

```ts
document.documentElement.dataset.theme = "dark";
delete document.documentElement.dataset.theme;
```

`data-theme` only sets `color-scheme`, and `color-scheme` inherits. You can therefore set it on any element, for example a dark section inside a light page. The nearest `data-theme` always wins.

`vite.config.ts` stops Lightning CSS from rewriting `light-dark()` for older browsers, because the rewritten version resolves at `:root` and would break nested sections. Native `light-dark()` needs Chrome 123, Safari 17.5 or Firefox 120 or later.

### Contrast

By default, contrast follows the operating system. If the user has turned on increased contrast (`prefers-contrast: more`), the high-contrast colors apply; otherwise standard contrast applies.

To choose a level explicitly, set `data-contrast` to `standard`, `medium` or `high`. An explicit value always wins over the system setting. On `<html>`, remove it or set it to `system` to follow the system again:

```ts
document.documentElement.dataset.contrast = "high";
delete document.documentElement.dataset.contrast;
```

Like `data-theme`, you can set it on any element to change only that part of the page, and it combines freely with `data-theme`.

In Storybook, use the **Palette**, **Theme** and **Contrast** controls in the toolbar. They set `data-palette`, `data-theme` and `data-contrast` on `<html>` for stories and for this page. The **System** options for theme and contrast follow your operating system. Storybook's own interface keeps the goat palette and follows your operating system's light/dark preference.

## Color roles

These are the 49 roles. Each one is available as `--md-sys-color-<role>`, for example `--md-sys-color-primary`.

### Accent colors (primary, secondary, tertiary)

| Token                                            | Use                                                                                                                        |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `primary`                                        | Main brand color, for the most prominent controls: filled buttons, active states, FABs, selected items.                    |
| `on-primary`                                     | Text and icons on `primary`.                                                                                               |
| `primary-container`                              | Softer, tonal version of primary, for less prominent emphasis such as tonal buttons, selected chips and highlighted cards. |
| `on-primary-container`                           | Text and icons on `primary-container`.                                                                                     |
| `secondary` / `on-secondary`                     | Less prominent accents, such as filter chips and secondary actions.                                                        |
| `secondary-container` / `on-secondary-container` | Tonal secondary elements, such as the active navigation indicator.                                                         |
| `tertiary` / `on-tertiary`                       | Contrasting accent, to add visual interest or highlight things like a special badge.                                       |
| `tertiary-container` / `on-tertiary-container`   | Softer tertiary emphasis.                                                                                                  |

### Error

| Token                                    | Use                                                                                       |
| ---------------------------------------- | ----------------------------------------------------------------------------------------- |
| `error` / `on-error`                     | Error messages and destructive actions, such as a delete button or invalid field outline. |
| `error-container` / `on-error-container` | Softer error backgrounds, such as an error banner.                                        |

### Surfaces (backgrounds of the UI)

| Token                                                                           | Use                                                                                                                                                                                    |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `surface`                                                                       | Default page and component background.                                                                                                                                                 |
| `on-surface`                                                                    | Main text and icon color.                                                                                                                                                              |
| `on-surface-variant`                                                            | Lower-emphasis text and icons, such as helper text, placeholders and inactive icons.                                                                                                   |
| `surface-container-lowest` → `low` → (`surface-container`) → `high` → `highest` | Five tones for layering containers. Higher tones stand out more from `surface`. Typical uses: cards (`low`), navigation bars (`container`), dialogs (`high`), text fields (`highest`). |
| `surface-dim` / `surface-bright`                                                | The darkest and lightest surface tones, used when you want a container to read as recessed or raised.                                                                                  |
| `surface-variant`                                                               | Legacy tone for variant surfaces. Newer M3 guidance uses the container tones instead.                                                                                                  |
| `surface-tint`                                                                  | Same color as primary. It's used to tint raised surfaces in older M3 designs.                                                                                                          |
| `background` / `on-background`                                                  | Legacy page background and text. They match `surface` and `on-surface` at standard contrast, so either pair works for the page body.                                                   |

### Lines and overlays

| Token             | Use                                                                           |
| ----------------- | ----------------------------------------------------------------------------- |
| `outline`         | Prominent borders, such as outlined buttons and text field borders.           |
| `outline-variant` | Subtle borders, such as dividers and card outlines.                           |
| `shadow`          | Color of drop shadows.                                                        |
| `scrim`           | Dimming layer behind modals, dialogs and drawers, applied at partial opacity. |

### Inverse

These are for elements that should contrast with the rest of the UI, mainly snackbars and tooltips.

| Token                | Use                                                                  |
| -------------------- | -------------------------------------------------------------------- |
| `inverse-surface`    | Background of the contrasting element (dark in light mode).          |
| `inverse-on-surface` | Text on `inverse-surface`.                                           |
| `inverse-primary`    | Accent color on `inverse-surface`, such as a snackbar action button. |

### Fixed

At standard contrast these colors are the same in light and dark mode. Use them where a color must not change with the theme, such as brand elements.

| Token                                 | Use                                                       |
| ------------------------------------- | --------------------------------------------------------- |
| `primary-fixed` / `primary-fixed-dim` | Fixed background, plus a slightly stronger version of it. |
| `on-primary-fixed`                    | Strong text on the fixed colors.                          |
| `on-primary-fixed-variant`            | Lower-emphasis text on the fixed colors.                  |

`secondary-fixed*` and `tertiary-fixed*` work the same way.

## Interaction states

The export doesn't include state-layer tokens. Instead, mix the content color over the container color at the M3 state-layer opacity: 8% for hover, 10% for focus and press, and 16% for drag.

```css
.button {
  background-color: var(--md-sys-color-primary);
  color: var(--md-sys-color-on-primary);
}

.button:hover {
  background-color: color-mix(
    in srgb,
    var(--md-sys-color-on-primary) 8%,
    var(--md-sys-color-primary)
  );
}
```

## Linting

`vpr lint:css:all` runs [Stylelint](https://stylelint.io/) on `src/**/*.css` and `.storybook/**/*.css`. It warns about colors that don't come from the theme. It checks every property ending in `color`, plus `background`, `border` (and its sides), `outline`, `text-decoration`, `fill` and `stroke`. These are allowed:

- `var()`
- `color-mix()`, but only if neither color is `transparent` and both colors are `var(--md-sys-color-*)` or `currentcolor`. Any color space, hue method and percentages are fine.
- `alpha()` to apply alpha to an existing color, such as `alpha(from var(--md-sys-color-primary) / var(--md-sys-state-disabled-content-opacity))`. Shared alpha values are named for their use in `opacity.css`; state-layer alpha values use the `--md-sys-state-*-state-layer-opacity` tokens.
- `transparent`, `currentcolor`, `none`, `url()` and global keywords such as `inherit`

Everything else gets a warning: hex, `rgb()`, named colors such as `red`, and a `color-mix()` or `alpha()` with a literal color in it. The files in `theme/` are exempt, because they define the tokens. The same rule checks fonts (see Foundations / Typography). It's configured in `stylelint.config.js`.

The rule doesn't look inside `box-shadow`, `text-shadow` or gradients, and it doesn't check inline styles in components.

## Syntax highlighting

`syntax.css` is a [Prism](https://prismjs.com/) theme built from the color roles. It's part of the shared styles, so it applies to any Prism-highlighted code on the site as well as Storybook's code blocks. It colors `.token` elements inside `pre` or `code`, and gives `pre[class*="language-"]` blocks a background, padding and rounded corners. The token rules start with `:root` so they override other Prism themes and Storybook's own syntax colors. Storybook's code blocks have no `language-` class, so `.storybook/syntax.css` sets their background.

Code follows the **Contrast** toolbar. Storybook's docs code blocks use Storybook's light or dark theme, like the rest of the docs page. That theme follows your system setting rather than the **Theme** toolbar. On the site, code follows the page's theme.

Syntax highlighting uses six accents derived from the existing palettes' standard
roles.

| Syntax accent | Source role       | Prism tokens                                                    |
| ------------- | ----------------- | --------------------------------------------------------------- |
| Keyword       | Goat `primary`    | `keyword`, `operator`, `atrule`, `tag`, `selector`, `important` |
| String        | Arctic `tertiary` | `string`, `char`, `attr-value`, `url`, `inserted`               |
| Function      | Arctic `primary`  | `function`, `function-variable`, `attr-name`                    |
| Number        | Goat `tertiary`   | `number`, `boolean`, `constant`, `symbol`                       |
| Type          | Arctic `primary`  | `class-name`, `builtin`; JSON `property`                        |
| Parameter     | Goat `error`      | `parameter`, `regex`, `deleted`                                 |

Plain text and punctuation use `on-surface`; comments use
`on-surface-variant`. Code blocks use `surface-container-low` as their
background. Accents meet 4.5:1 contrast in standard mode, 6:1 in medium mode,
and 7:1 in high mode against both palettes' code backgrounds. Medium and high
contrast adjust light-mode tones; dark-mode accents remain unchanged.

```tsx
import { useState } from "react";

// Toggles the saved state.
export function SaveButton({ label = "Save" }: { label?: string }) {
  const [saved, setSaved] = useState(false);
  return (
    <button type="button" className="button" onClick={() => setSaved(true)}>
      {saved ? "Saved" : label} {42}
    </button>
  );
}
```

```css
@media (prefers-contrast: more) {
  .button:hover {
    color: var(--md-sys-color-on-primary);
    padding: 0.5rem 1rem;
  }
}
```

## Updating the export

1. Add or replace the six files in `theme/exports/<name>/` with a Material Theme Builder CSS export. Keep the names `light.css`, `dark.css`, `light-mc.css`, `dark-mc.css`, `light-hc.css` and `dark-hc.css`. Their selectors don't matter, because only the token declarations are read.
2. Run `vp run theme:generate`. It discovers each theme directory and regenerates `palettes/<name>.gen.css`. It also regenerates `.storybook/palette.gen.ts` from goat, which holds the literal colors for Storybook's own interface (that interface can't read CSS variables). Don't edit generated files by hand.
3. Goat and arctic are imported by `theme/index.css` and selected with `data-palette` on `<html>`. To expose another generated palette, import it there and add its palette/contrast selectors and a Storybook toolbar item.
